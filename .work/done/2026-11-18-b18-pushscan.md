# b18 pushscan (worker D3)

## Goal
BACKLOG row "pre-push hook": CI has no private-terms list, so only a local
full check.sh scans. A PreToolUse hook now runs `bash scripts/private-terms.sh
check` in the repository a `git push` targets and blocks (exit 2) when it fails.

## Acceptance criteria and evidence
- Push forms refused when the scan fails: git push, with remote/ref/options,
  `git -c k=v push`, `git.exe push`, `env X=1 git push`, `sudo git push`,
  `bash -c "git push ..."`, `cmd && git push`, `a; git push`, `cd DIR && git push`,
  `git -C DIR push` (tests: "staged term blocks" x11, unpushed commit, git -C group).
- Push forms allowed: clean push (9 forms), no terms file, repo without
  scripts/private-terms.sh (note on stderr), directory outside a repository
  (note on stderr), `git push --help`, `git push -h`.
- Non-push commands allowed with the term staged and never run the scan: git status/log/fetch/
  pull/diff/stash push/help push, commit with "push" in the message, echo/grep mentioning push
  (fake private-terms.sh records calls; calls.log must not exist; a run with an empty PATH proves builtins only).
- `git -C DIR push` targets DIR (relative -C composes with the payload cwd); `cd` tracked.
- Malformed payload: parsed as a whole-text command like destructive-guard.sh (its policy: no
  "command" field -> scan the whole payload text); a warning goes to stderr; allow unless that
  text is a push whose scan fails. Empty stdin allows. A hook-internal error exits 1
  (non-blocking), unlike the guard which fails closed: this hook is a habit guard, not a data guard.
- Wiring: .claude/settings.json (Bash|PowerShell, timeout 60, after destructive-guard), .codex/hooks.json
  (Bash, third PreToolUse hook, commandWindows routed via scripts/codex-hook.cmd push-scan, fail-open).
- Timeout: see the measured time in the test ("a push scan ... takes N s").

## Forms (L012)
Refuse: see criteria. Allow: see criteria. Not covered (limits, in the script header): --git-dir/--work-tree
targets, eval, aliases, pushes inside scripts, cd to a variable.

## Decisions
- Scan runs the TARGET repository's own scripts/private-terms.sh (it cds to its own root); a target without it allows.
- Codex entry is third (index 2) so existing HOOK_I indices in test_codex_hooks.sh are unchanged.
- Codex launcher fails open for push-scan (FAILRC 0), as for the shell-stdin hook.
- One line each in docs/rules/security.md (now 37 lines, cap 40) and docs/procedures/ship.md.
